# v1.1.0 — Security & Hardening Release

## Security fixes

- **Path traversal protection** — All workspace file operations now validate identifiers and paths against traversal attacks before any filesystem access
- **IPC boundary hardening** — Removed unrestricted file read/write channels from the preload bridge; all IPC handlers validate and sanitize inputs in the main process
- **Sandbox enabled** — Electron renderer sandbox is now active, adding a containment layer if renderer code is compromised
- **Navigation & permission guards** — External navigation, new windows, and permission requests are blocked or tightly restricted; dev server URL is validated to localhost only
- **Content Security Policy** — CSP directives extended to restrict object sources, base URIs, frame ancestors, form actions, and connect sources
- **CSV formula injection** — Exported CSV values beginning with `=`, `+`, `-`, `@`, tab, or carriage return are neutralized to prevent spreadsheet formula execution
- **Frontmatter sanitization** — YAML-like frontmatter fields are now escaped to prevent injection or corruption of metadata
- **Strict input validation** — Zod schemas enforce ISO date formatting, hex color format, safe identifier patterns, and maximum collection sizes on all import/export boundaries
- **File size limits** — Maximum file size limits enforced for reads, writes, and imports to prevent resource exhaustion
- **Cryptographic identifiers** — Replaced non-cryptographic ID generation with `crypto.randomUUID()`
- **Storage path trust boundary** — Renderer can no longer change a workspace's `storagePath` after creation; changes now require a native OS folder dialog confirmed in the main process
- **Improved error handling** — Structured error returns replace silent failures for better auditability

## Dependency upgrades

- Electron 33.x → 42.x
- electron-builder 25.x → 26.x
- Vitest 2.x → 4.x
- Removed unused dependencies (`uuid`, `rehype-raw`)

## Functionality fixes

- Workspace custom storage paths now resolve correctly to user-selected directories
- Notes are explicitly saved when navigating away from the editor (no more lost content on back)
- Workspace isolation ensured — workspace data directories are never shared between workspaces
